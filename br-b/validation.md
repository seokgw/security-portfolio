공개 접근 검사는 Playwright가 새로 생성한 쿠키·로그인 없는 비공개 컨텍스트에서 수행했다. 사용자가 직접 Ctrl+Shift+N으로 연 가시적인 시크릿 창 검사는 별도 수행하지 않았다. 검증 URL과 방법은 public-access.json에 기록했다.

동작 검사: 빈 값 / -1 / abc / 25 안내, 필수 목적·빈도 누락 안내, 0과 24 허용, 환경 미선택 허용, 휴식 도움과 수면 방해 동시 선택의 안내, 결과 표시, 초기화, 모바일 390px 가로 넘침 없음. 데스크톱·모바일 결과와 대표작 캡처를 시각 검토했다.

자동 검사는 한국어 실명이나 부대명을 완전 탐지하지 못한다. 공개 페이지의 문맥은 본인 이름과 익명 역할 표현을 유지하며, 앱에는 자유 서술·신원 입력란이 없다. 이전 공개용 사본의 익명화는 유지했다.

실제 동료에게 「이 앱을 처음 보는 사람처럼 한번 사용해 보고 한 줄로 느낌을 적어 주세요」라고 전달하고 이름 없이 받은 원문을 대표작과 submission.md에 반영해야 전체 통과한다. 의미를 모르겠다는 반응이면 첫 화면 설명을 보완하고 다시 사용하게 한다.


## 날짜별 DB 저장 확장 검수

아래 확장은 초기 배포 검수 이후 추가한 기능이다. 점검·결과 확인은 비로그인 공개 기능을 유지하고, 저장·조회에만 GitHub OAuth를 사용한다.

- 목적 9개, 환경 요소 14개, 선택 사항 6개(체감 스트레스·소통·휴식, 수면시간, 사용 시간대·기분) 추가.
- 날짜당 한 기록 저장·수정, 이전 날짜 비교, CSV 내려받기 구현.
- 로컬 모의 DB 테스트 PASS: 실패 시 입력 유지, 날짜별 생성·수정·비교, 입력 변경 후 재확인, 잘못된 날짜·수면 검증, 브라우저 데이터 삭제 후 재로그인 복구, 로그아웃 격리, 모바일 너비. 모의 DB 검사는 실제 Supabase 저장 증명이 아니다.
- 실제 전용 DB 읽기 전용 점검 PASS: RLS 활성화, 비로그인 SELECT 권한 없음, 본인 ID 정책 4개.
- 실제 공개 API 확인 PASS: GitHub enabled=true, 비로그인 기록 조회 HTTP 401.
- 운영 DB에 가상 auth.users를 생성하는 시험은 자동 승인 검토가 거부해 실행하지 않았다. 두 계정 간 실제 접근 격리 테스트는 미실시다.
- 실제 사용자 OAuth와 저장·재조회는 배포 후 확인 예정.
