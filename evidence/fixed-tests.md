# 과제 5 고정 검사 10개

구현을 시작하기 전에 고정한다. 작업 도중 삭제·완화·기대값 변경을 하지 않는다.

참조 원본: `t04-real-information-board` (과제 4, 변경 금지)
검사 대상: `assignment5-real-information-board` (과제 5)
개선 기능: 데이터 상태(`fresh` / `stale` / `error`)와 마지막 정상값을 사용자가 명확히 구분할 수 있는 상태 표시 영역 개선

---

## T5-TEST-01 정상 상태 표시
- 입력: 정상 데이터 조회(`실제 값 조회`) 또는 프로젝트에 정의된 정상 재생 fixture(D1-A → D1-B)를 실행한다.
- 기대값: 화면에서 현재 상태가 `fresh`임을 사용자가 확인할 수 있다.

## T5-TEST-02 정상 값 표시
- 입력: 정상 데이터 조회를 실행한다.
- 기대값: 현재 값과 단위가 화면에 표시된다.

## T5-TEST-03 출처 표시
- 입력: 정상 데이터 조회를 실행한다.
- 기대값: 데이터 출처 또는 출처 URL을 사용자가 확인할 수 있다.

## T5-TEST-04 조회/관측 시각 표시
- 입력: 정상 데이터 조회를 실행한다.
- 기대값: 출처 관측 시각 또는 조회 시각이 화면에 표시된다.

## T5-TEST-05 실패 후 stale 표시
- 입력: 정상 값을 한 번 확보한 뒤(D1-A → D1-B) 프로젝트에 존재하는 실패 재생 fixture 중 하나(timeout/auth-401/rate-429/offline/schema-break)를 실행한다.
- 기대값: 마지막 정상값은 유지되고 상태가 `stale`임을 사용자가 확인할 수 있다.

## T5-TEST-06 stale 설명 표시
- 입력: 마지막 정상값이 있는 상태에서 실패 상황을 실행한다.
- 기대값: 현재 값이 새 데이터가 아니라 마지막 정상값이라는 설명이 화면에 표시된다.

## T5-TEST-07 정상값 없는 오류
- 입력: 마지막 정상값이 없는 초기 상태(reset 직후)에서 실패 상황을 실행한다.
- 기대값: 존재하지 않는 값을 임의로 표시하지 않고 `error` 또는 데이터 없음 상태가 표시된다.

## T5-TEST-08 복구 후 fresh
- 입력: `stale` 또는 `error` 상태를 만든 뒤 정상 조회 또는 기존 recover 기능(recover-d2 / 다시 시도)을 실행한다.
- 기대값: 상태가 다시 `fresh`로 바뀐다.

## T5-TEST-09 새로고침 후 상태 일관성
- 입력: 현재 프로젝트에서 보존하도록 정의된 상태(localStorage)를 만든 뒤 브라우저를 새로고침한다.
- 기대값: 기존 과제 4에서 정의한 저장 정책(localStorage 키 `aleph-t04-live-v1` / `aleph-t04-replay-v1`)에 맞게 상태와 값이 일관되게 표시된다. 기존 저장 정책을 임의로 바꾸지 않는다.

## T5-TEST-10 경계 화면 확인
- 입력: 1366×768 브라우저 크기에서 개선된 상태 표시 영역을 확인한다.
- 기대값: 상태, 값, 설명이 화면 밖으로 잘리거나 겹치지 않는다.
