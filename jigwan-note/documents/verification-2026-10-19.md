# 직관노트 실제 계정 검증 — 2026-10-19

대상: https://jigwan-note.vercel.app/

샘플 모드가 아닌 테스트 전용 Supabase 이메일/비밀번호 계정으로 진행했다. 기능 검증용 계정은 관리자 DB 작업으로 이메일 인증 완료 상태로 생성했다. 따라서 이 계정 생성 자체는 신규 가입 메일 발송·수신 검증을 대신하지 않는다.

| 항목 | 결과 | 확인한 증거 |
|---|---|---|
| 실제 로그인 | 통과 | 테스트 계정 이메일 표시, 빈 개인 대시보드 진입 |
| 응원팀 저장 | 통과 | 한화 이글스 저장 후 상단 팀명 변경, auth.users 메타데이터 저장값 확인 |
| 로그아웃·재로그인 | 통과 | 재로그인 후 상단 한화 이글스 유지, 새 기록의 팀 자동 입력 |
| 기록 등록 | 통과 | 대전 구장, 한화–LG, 5:3 승리, 후기·좌석 입력 후 DB 행 생성 |
| 사진 첨부·업로드 | 통과 | 직접 생성한 640×360 PNG 첨부, private Storage JPG 경로와 DB photos 1개 확인 |
| 새로고침 후 조회 | 통과 | 서버 저장 기록 1건과 사진 재조회, 이미지 complete=true 및 naturalWidth=640 확인 |

| 신규 가입 이메일 인증 | 통과 | 수신 메일의 Supabase 인증 링크 처리 성공, auth.users.email_confirmed_at 실제 설정 확인 |

## 검증 과정의 제한

- 삭제 확인창에서 브라우저 자동화가 시간 초과를 반환했다. 이후 Supabase 요청 로그에서 실제 브라우저의 삭제 요청 성공과 DB·Storage 삭제 완료를 확인했다. API 대체 스크립트는 이미 삭제된 행을 다시 읽으려다 중단됐으며, 이를 앱 삭제 실패로 판정하지 않았다.
- 개인 수신함에 접근하지 않았다. 사용자에게 [mail.tm](https://mail.tm) 임시 수신함으로 테스트 인증 링크를 보내도 된다는 승인을 받은 뒤 실제 발송·수신·인증을 확인했다. 임시 수신함은 삭제했다.
- 메일 발송 시각은 2026-10-19 14:51:47 KST, 서버의 인증 완료 시각은 14:52:00 KST였다. 이번 테스트 환경에서의 수신 성공이며 모든 메일 서비스에 대한 전달 보장은 아니다.
- 물리적인 휴대폰이 아닌 모바일 뷰포트에서 점검했다.

## 정리

- 기능 테스트 계정의 전체 세션 종료 API 성공을 확인했다.
- 테스트 계정 2개 삭제는 연결 도구 오류와 관리 화면 로그인 만료로 지연됐으나, 사용자가 로그인한 뒤 관리 화면에서 두 테스트 ID를 대조해 선택하고 삭제했다. 최종 DB 조회로 테스트 사용자·경기 기록·사진이 모두 0개임을 확인했다.
- 테스트 경기 기록과 사진은 모두 삭제됐으며 기존 사용자 데이터 및 plan-do-see 설정은 변경하지 않았다.
- 임시 인증 스크립트는 삭제했다. 보고서에 비밀번호, API 키, 세션 토큰, 서명 URL을 남기지 않았다.
- 테스트 이미지 `test-photo.png`는 개인정보 없는 자체 생성 검증 자료다.
