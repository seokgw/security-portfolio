# 야구 직관 기록 웹앱 개발 계획

## 1. 프로젝트 목표
야구 팬이 직접 관람한 경기를 기록하고, 사진과 후기를 모아 보며, 직관 결과와 관람 통계를 확인할 수 있는 개인용 반응형 웹앱을 만든다.

## 2. 대상 사용자와 핵심 가치
- **대상 사용자:** 야구장 직관 경험을 꾸준히 기록하고 싶은 야구 팬
- **핵심 가치:** 경기 기록을 간편하게 남기고, 과거 관람 추억과 팀·구장별 성적을 한눈에 확인한다.

## 3. 핵심 기능
1. **직관 기록 관리**
   - 기록 등록, 상세 조회, 수정, 삭제
   - 입력: 경기 날짜, 구장, 응원 팀(선택), 상대 팀, 경기 결과, 양 팀 점수, 좌석, 사진, 후기
2. **통계 대시보드**
   - 총 직관 횟수 및 승·무·패
   - 직관 승률: 무승부 제외, 승리 ÷ (승리 + 패배)
   - 구장별 관람 횟수, 빈 상태 안내
3. **직관 히스토리**
   - 날짜순 목록·상세, 팀/구장 필터, 최신순·과거순 정렬, 모바일 대응
4. **계정 및 서버 저장**
   - 사용자 계정 연결, 본인 기록만 조회·변경
   - localStorage가 아닌 서버 DB에 영속 저장

## 4. 화면 및 사용자 흐름
- 로그인/회원가입 → 대시보드 → 기록 추가 → 목록/상세 → 통계 갱신
- 기록 상세에서 수정 또는 확인 후 삭제

## 5. 데이터 항목
| 항목 | 형식 | 비고 |
|---|---|---|
| id | 텍스트 ID | 앱 생성 |
| user_id | UUID | 계정 소유자, RLS 적용 |
| game_date | 날짜 | 필수 |
| stadium | 문자열 | 필수 |
| favorite_team | 문자열 | 선택 |
| opponent_team | 문자열 | 필수 |
| favorite_score / opponent_score | 정수 | 함께 입력하거나 생략 |
| result | win/draw/loss | 필수, 점수와 일관성 확인 |
| seat / review | 문자열 | 선택 |
| photos | Storage 경로 목록 | 비공개 저장소, 서명 URL 제공 |
| created_at / updated_at | 날짜·시간 | 서버 관리 |

## 6. 확정된 선택
- Supabase Auth + PostgreSQL 사용
- `watch_records` 테이블의 사용자별 RLS로 계정 간 기록 격리
- private Storage bucket에 사진을 보관
- 팀 이름은 자유 입력. 응원 팀 미지정은 결과 직접 선택/점수 미입력. 응원 팀 지정 시 양쪽 점수를 같이 입력하거나 모두 생략하며, 점수 입력 시 결과와 일치해야 함.
- 프런트엔드에는 공개 anon key만 사용하고 service_role 키를 넣지 않음
- 기존 브라우저 localStorage 기록은 자동 이전하지 않음

## 7. 개발 단계 및 진행 상황
### 단계 1 — 요구사항·화면 설계: 완료
- 필수/선택 항목과 입력 규칙 확정
- 모바일 우선 레이아웃 및 사용자 흐름 정의

### 단계 2 — 기본 화면·데이터 구조: 구현됨
- 대시보드, 목록, 상세, 등록/수정 화면 및 검증
- Supabase 인증 화면, DB 스키마와 RLS 초안

### 단계 3 — CRUD·사진: 코드 연결됨
- 기록 CRUD를 인증된 사용자의 Supabase DB에 연결
- 사진 업로드를 private Storage에 연결
- 실제 프로젝트에 설정·배포 전에는 동작 확인되지 않음

### 단계 4 — 통계·탐색: 구현됨
- 승·무·패, 승률, 구장 통계, 팀 검색·구장 필터·날짜 정렬

### 단계 5 — 실제 설정·검증·배포: 미완료
- Supabase 실제 프로젝트 생성, SQL 실행 및 키 입력 필요
- 브라우저 CRUD·사진·계정 격리·모바일 시나리오와 배포 확인 필요

## 8. 완료 검증 기준
- 5건 이상 기록 가능
- 등록/조회/수정/삭제 결과가 목록과 통계에 반영
- 승·무·패와 승률 계산 정확
- 구장 통계, 팀·구장 필터, 날짜 정렬 정상
- 사진과 후기가 상세 화면에 연결
- 다른 계정의 데이터가 보이지 않음
- 좁은 모바일 화면 사용 가능
- 재로그인 후 서버 DB 데이터 유지

## 9. 남은 운영 작업
- Supabase 프로젝트 생성 후 `supabase-schema.sql` 실행
- `supabase-config.js`에 Project URL 및 anon/public key 입력
- Auth 이메일 인증/배포 도메인 설정
- 실제 브라우저에서 기능·보안·모바일 점검
- 기존 localStorage 기록은 필요하면 수동 재등록
- 백업, 개인정보 안내 및 계정 삭제 정책 확인
