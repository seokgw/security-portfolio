# 개인 자료 보관함

## 사용 방법

패스키 로그인 후 **내 자료 보관함**에서 제목·내용을 입력하고 메모 저장을 누른다. 저장한 메모의 **열기 / 수정**으로 내용을 다시 열고 편집한다. **파일 보관**에서는 제목과 파일을 선택해 저장한다. 메모와 파일 모두 다운로드·삭제할 수 있다. 기존 샘플 메모는 별도 접이식 영역으로 유지한다.

파일당 5MB, 계정당 50MB/200개, 서비스 전체 500MB 한도를 적용했다. 제목은 160자, 메모 내용은 50,000자까지다. 동시에 다른 창에서 수정한 메모는 충돌로 거절한다. 삭제는 보관함에서 복원할 수 없다.

## 보관 및 접근 제어

`vault.js`의 `/api/vault` API는 목록·생성·조회·메모 수정·삭제·다운로드 모두 서버 세션을 검사한다. 모든 SQL 조회·변경은 인증된 계정 ID로 제한하며, 다른 계정의 자료 ID는 404로 거절한다. 요청의 userId/accountId가 다르면 403이다. 파일 경로를 사용자 입력으로 만들지 않는다.

제목·원본 파일명·메모·파일 내용은 Node crypto의 AES-256-GCM으로 암호화해 기존 SQLite `vault` 테이블에 저장한다. 각 암호문은 새 96비트 난수 IV와 인증 태그를 사용하며 계정·자료 ID·필드 구분을 AAD로 묶는다. 키는 별도 `vault.key` 파일에 저장하고 운영에서는 서비스 사용자만 읽도록 0600 권한을 적용한다. 키를 찾지 못했는데 기존 자료가 있으면 새 키를 만들어 덮어쓰지 않고 기동을 거절한다.

운영 데이터: `/var/lib/portfolio-passkey/passkeys.sqlite`

운영 암호화 키: `/var/lib/portfolio-passkey/vault.key`

이 경로들은 GitHub 저장소 및 웹 정적 경로 밖에 있다. 내용·파일명은 감사 로그에 남기지 않는다. 파일은 `application/octet-stream`, `Content-Disposition: attachment`로 내려주며 웹페이지 안에서 실행하거나 미리 보지 않는다. 화면은 textContent로 제목을 표시한다. 로그아웃·인증 만료 시 작성란과 조회 자료를 비운다.

## 보호 범위와 한계

**서버가 복호화 키를 관리한다. 종단간 암호화가 아니므로 서버 관리자 또는 서버 전체를 침해한 공격자는 복호화할 수 있다.** DB 파일만 유출된 경우의 내용 보호와 계정 간 접근 차단을 제공한다. 계정 ID·자료 종류·크기·시각은 암호화하지 않는다. 기기에서 다운로드한 사본은 사용자가 관리한다.

별도 악성코드 검사는 하지 않으며 저장 파일을 서버에서 실행하지 않는다. 공개 가입이 가능한 단일 VM 서비스여서 대량 가입·저장소 고갈을 완전히 막지는 못한다. 삭제 후 SQLite·백업 잔존 데이터에 대한 물리적 완전 삭제는 보장하지 않는다. 정기적인 외부 백업·재해 복구와 관리자 접근 통제는 별도 운영 작업이다. 패스키를 모두 잃거나 마지막 패스키를 삭제하면 계정 복구 수단이 없다.

업그레이드 시 기존 DB를 `/var/backups/portfolio-passkey/시간/`에 먼저 복사한다. 이후 백업할 때는 DB와 원래 `vault.key`를 반드시 함께, 접근을 제한한 위치에 보관해야 한다. 키를 잃으면 저장 자료를 복구할 수 없다.
