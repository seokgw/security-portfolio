브라우저에서 실행되는 **같은 그림 찾기(Memory Card Matching) 미니게임​**을 만들어줘.

이 프로젝트는 과제 제출용이며, 단순히 게임이 실행되는 것뿐 아니라 아래의 과제 평가 기준과 테스트 조건, GitHub 공개 배포 조건까지 모두 충족해야 한다.

게임은 가능한 한 단순하고 안정적으로 구현하고, 과도한 기능 추가보다는 **명확한 규칙, 안정적인 상태 관리, 테스트 가능성​**을 우선한다.

# 1. 기술 구성

다음 기술만 사용한다.

- HTML
- CSS
- Vanilla JavaScript
- 별도 백엔드 없음
- 로그인 없음
- 외부 API 없음
- API Key / Secret Key 없음
- GitHub 저장소에 그대로 업로드 가능
- GitHub Pages로 정적 배포 가능

가능하면 외부 라이브러리나 프레임워크는 사용하지 않는다.

프로젝트 구조는 다음처럼 구성한다.

```text
memory-card-game/
├─ index.html
├─ css/
│  └─ style.css
├─ js/
│  └─ game.js
├─ assets/
│  └─ images/
├─ README.md
└─ .gitignore
```

# 2. 게임 기본 컨셉

게임 제목은 임시로 다음과 같이 한다.

**PAIR UP! - 같은 그림 찾기**

화면에 카드 여러 장을 뒤집어서 배치한다.

각 그림은 정확히 두 장씩 존재한다.

플레이어가 카드 두 장을 선택해서 같은 그림을 찾는 게임이다.

카드는 처음에는 모두 뒷면이 보인다.

첫 번째 카드를 클릭하면 앞면을 보여준다.

두 번째 카드를 클릭하면 두 카드의 그림을 비교한다.

## 같은 그림이면

- 두 카드를 열린 상태로 유지
- 다시 클릭할 수 없도록 처리
- 점수 +100
- 맞춘 쌍 수 +1

## 다른 그림이면

잠깐 그림을 보여준 뒤 두 카드를 다시 뒤집는다.

두 장을 비교하고 있는 동안에는 세 번째 카드를 클릭할 수 없도록 입력을 잠근다.

한 번의 클릭은 게임 상태에 정확히 한 번만 반영되어야 한다.

# 3. 기본 게임 설정

제한시간은 모든 난이도에서 동일하게 고정한다.

```javascript
const GAME_TIME = 30;
```

게임 시작 후 반드시 **30초 안에 성공 또는 실패 상태에 도달할 수 있어야 한다.**

기본 카드 개수는 난이도 실험에 따라 변경할 수 있도록 하나의 변수로 관리한다.

예:

```javascript
const CARD_PAIR_COUNT = 6;
```

카드 쌍 수를 기준으로 실제 카드는 자동 생성한다.

```javascript
const totalCards = CARD_PAIR_COUNT * 2;
```

# 4. 카드 이미지

총 8종 이상의 서로 구분하기 쉬운 그림이나 아이콘을 준비한다.

예:

```javascript
const CARD_ICONS = [
  "🍎",
  "🍋",
  "🍇",
  "🍒",
  "🥝",
  "🍉",
  "🍓",
  "🍊"
];
```

별도 이미지 파일을 사용해도 되지만 과제 구현 안정성을 위해 이모지 또는 직접 만든 단순 아이콘을 사용해도 된다.

`CARD_PAIR_COUNT`에 필요한 만큼만 사용한다.

예:

6쌍이면 앞의 6개 아이콘 사용.

8쌍이면 8개 아이콘 모두 사용.

각 아이콘은 두 장씩 생성한 뒤 배열을 랜덤하게 섞는다.

# 5. 성공 / 실패 조건

## 성공 조건

제한시간 30초가 끝나기 전에 모든 카드 쌍을 찾으면 성공한다.

화면에 명확하게 표시한다.

```text
CLEAR!
모든 카드를 찾았습니다.
점수: XXXX
```

게임 상태:

```text
상태: CLEAR
```

## 실패 조건

30초가 되었는데 모든 카드 쌍을 찾지 못했다면 실패한다.

```text
TIME OVER
찾은 카드: X / X
점수: XXXX
```

게임 상태:

```text
상태: TIME OVER
```

성공 또는 실패가 확정되면

- 시간 정지
- 카드 입력 정지
- 추가 점수 획득 금지
- 게임 상태 변경 금지

처리한다.

# 6. 30초 핵심 게임 루프

게임 흐름은 다음과 같아야 한다.

```text
게임 시작
↓
카드 선택
↓
두 카드 비교
↓
같으면 점수 획득
↓
계속 카드 찾기
↓
30초 안에 성공 또는 실패
↓
다시 시작
```

시작 → 진행 → 성공/실패 → 재시작이 끊기지 않고 이어져야 한다.

# 9. 다시 시작

화면에 다음 버튼을 만든다.

```text
다시 시작
```

성공 후 다시 시작할 수 있어야 한다.

실패 후 다시 시작할 수 있어야 한다.

재시작하면 반드시 현재 판 상태를 완전히 초기화한다.

초기화 대상:

- 현재 점수
- 남은 시간
- 첫 번째 선택 카드
- 두 번째 선택 카드
- 현재 열린 카드
- 맞춘 카드
- 맞춘 쌍 수
- 게임 상태
- 입력 잠금 상태
- 일시정지 상태
- interval
- timeout
- 성공/실패 효과 상태

카드도 새로 랜덤하게 섞는다.

기존 setInterval이나 setTimeout이 남아서 중복 실행되지 않도록 반드시 정리한다.

# 10. PC 해상도 대응

다음 환경을 모두 지원한다.

```text
1366 × 768
1920 × 1080
```

두 해상도에서 모두 다음 조건을 만족해야 한다.

- 카드 잘림 0건
- 버튼 잘림 0건
- 조작 영역 잘림 0건
- 가로 스크롤 0건
- 화면 바깥으로 UI가 넘어가지 않음

CSS Grid를 사용해 카드 영역을 반응형으로 구성한다.

카드가 12장일 때와 16장일 때 모두 화면이 정상적으로 보여야 한다.

예:

12장:

```text
4 × 3
```

16장:

```text
4 × 4
```

필요하다면 CSS Grid의 열 수를 카드 개수에 따라 자동 조정한다.

# 11. 창 크기 변경

- 점수
- 시간
- 열린 카드
- 맞춘 카드
- 게임 상태
- 현재 진행 상황

# 12. 빠른 연속 입력 검사

과제에서는 1초 안에 동일한 핵심 입력 이벤트를 10건 발생시키는 검사를 한다.

빠르게 클릭해도 이벤트 1건당 핵심 동작이 정확히 1번만 처리되게 한다.

다음을 방지한다.

- 같은 카드 두 번 선택
- 이미 맞춘 카드 다시 선택
- 비교 중 세 번째 카드 선택
- 점수 중복 증가
- 같은 쌍 중복 처리
- 이벤트 리스너 중복 등록
- setInterval 중복 생성

게임을 다시 시작할 때 이벤트 리스너가 계속 누적되지 않게 한다.

가능하면 이벤트 위임 또는 최초 1회 이벤트 등록 구조를 사용한다.

# 13. 브라우저 포커스 처리

브라우저 탭을 변경하거나 창의 포커스를 잃으면 게임을 자동으로 일시정지한다.

예:

```javascript
document.addEventListener("visibilitychange", ...)
window.addEventListener("blur", ...)
window.addEventListener("focus", ...)
```

포커스를 잃으면:

```text
상태: 일시정지
```

이 상태에서는

- 제한시간 감소 금지
- 카드 클릭 금지
- 카드 비교 진행 금지
- 게임 상태 변경 금지

다시 돌아오면 기존 상태에서 이어서 플레이할 수 있어야 한다.

포커스를 잃었던 시간만큼 제한시간이 한 번에 감소하면 안 된다.

# 15. 10분 연속 실행 안정성

브라우저에서 게임을 여러 번 반복 실행하고 재시작하면서 10분 이상 실행해도 정상적으로 조작할 수 있어야 한다.

다음을 방지한다.

- 이벤트 리스너 누적
- interval 누적
- timeout 누적
- 게임 속도가 점점 빨라지는 문제
- 카드 클릭이 중복되는 문제
- 메모리 누적으로 인한 오작동
- Console Error

10분 후에도 게임을 계속 플레이할 수 있어야 한다.

Chrome 개발자 도구 Console의 빨간 JavaScript 오류는 0건이어야 한다.

# 16. 난이도 비교

이 과제에서 난이도 비교 값은 **시간이 아니라 카드 개수**이다.

제한시간은 항상 30초로 고정한다.

두 실험 사이에서 변경할 수 있는 난이도 값은 **카드 개수 하나뿐이다.**

## 실험 A

```text
카드 12장
같은 그림 6쌍
CARD_PAIR_COUNT = 6
제한시간 = 30초
10회 플레이
```

## 실험 B

```text
카드 16장
같은 그림 8쌍
CARD_PAIR_COUNT = 8
제한시간 = 30초
10회 플레이
```

코드는 다음처럼 설정한다.

변경 전:

```javascript
const CARD_PAIR_COUNT = 6;
const GAME_TIME = 30;
```

변경 후:

```javascript
const CARD_PAIR_COUNT = 8;
const GAME_TIME = 30;
```

두 실험 사이에서는 `CARD_PAIR_COUNT`만 변경한다.

다음 값은 절대로 변경하지 않는다.

- 제한시간 30초
- 매칭 성공 점수 100점
- mismatch 대기시간
- 카드 크기
- 카드 뒤집기 방식
- 애니메이션 속도
- 랜덤 섞기 방식
- 조작 방식
- 성공/실패 판정 방식
- 화면 효과
- 저장 방식

# 18. 최종 난이도 판단

20회 테스트 후 사용자가 12장 또는 16장 중 최종 난이도를 직접 결정한다.

최종 난이도 선택 이유는 느낌만으로 작성하지 않는다.

다음 기록과 연결한다.

- 10회 중 성공 횟수
- 실패 횟수
- 클리어 시간 중앙값
- 점수 범위
- 반복되는 실패 원인

예시 문장은 참고용으로만 README에 제공한다.

```text
12장에서는 10회 중 10회 성공했고 클리어 시간 중앙값이 17초였다.

16장에서는 10회 중 7회 성공했고 성공한 판의 클리어 시간 중앙값이 25초였다.

실패한 3회는 모두 제한시간 안에 마지막 카드 쌍을 찾지 못해서 발생했다.

따라서 30초 안에 성공 가능하면서도 난이도가 충분한 16장을 최종값으로 선택했다.
```

이 문장을 그대로 제출하게 하지 말고 실제 테스트 결과에 맞게 수정하도록 명시한다.

# 19. 저장 데이터 설계

localStorage를 사용한다.

## 새 게임마다 초기화하는 값

다음은 localStorage에 저장하지 않는다.

- 현재 점수
- 현재 남은 시간
- 현재 카드 배열
- 현재 열린 카드
- 현재 맞춘 카드
- 현재 선택 카드
- 현재 게임 상태

다음만 저장한다.

```text

누적 성공 횟수
```

예:

```javascript
{

  totalWins: 5
}
```

화면에는 다음처럼 표시한다.

```text
BEST 800
PLAY 12
WIN 5
```

# 21. 손상된 저장값 복구

localStorage 데이터가 손상되어도 게임이 멈추면 안 된다.

예:

```text
abc
```

또는

```json
{"bestScore":"ERROR"}
```

또는

```json
{"bestScore":null,"totalGames":[]}
```

같은 데이터에서도 JavaScript 오류가 발생하지 않아야 한다.

반드시

- try/catch
- JSON 형식 검사
- 데이터 타입 검사
- 숫자 유효성 검사

를 한다.

잘못된 데이터라면 자동으로 기본값으로 복구한다.

복구 후에는 게임 화면, 상태, 타이머까지 정상적으로 시작되어야 한다.

효과는 성공 순간 정확히 한 번 실행되어야 한다.

다음 상황에서는 실행되면 안 된다.

- 일반 카드 클릭
- 카드 mismatch
- 게임 시작
- 일시정지
- TIME OVER

성공 상태가 유지되는 동안 효과가 계속 반복되지 않게 한다.

특히 중요한 점은 난이도를 조절하기 위해 **제한시간을 변경하지 않는 것**이다.

제한시간은 항상 30초로 고정한다.

```javascript

```

```text

vs
16장 / 8쌍 / 30초
```

다른 게임 설정은 전부 동일하게 유지한다.

**30초 안에 핵심 게임 루프가 분명하고, 재시작·PC 환경·난이도 비교·저장 복구·효과 선택권·GitHub 공개 배포까지 검증할 수 있는 안정적인 같은 그림 찾기 게임**
